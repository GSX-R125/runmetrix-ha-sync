# Runmetrix RDM Sync 0.3.6

RDMのアクティビティ一覧から、表示中の未保存の活動を取得します。画面の「一括」CSV出力で得たZIPを `YYYYMMDDHHMM.zip` として保存し、フォームdata・score CSVをZIP内の元の名前のまま展開します。

## 初回設定

1. OneASICSの同じアカウントで、メールアドレスとパスワードによるRDMログインができることを、ご自身のブラウザーで確認します。Google連携で作ったアカウントの場合は別アカウントを作らないでください。
2. インストール後、アプリの情報画面に表示されるIDを確認します。`\\homeassistant\addon_configs\<アプリID>\rdm_credentials.json` を作り、次の形式で保存します。SMB共有が `app_configs` と表示される環境では、その共有を使います。ローカルインストール時のIDは `local_runmetrix_sync`、GitHubリポジトリからのインストール時は異なる接頭辞になります。

   ```json
   {"email": "OneASICSに登録したメールアドレス", "password": "OneASICSのパスワード"}
   ```

   このファイルはアプリ専用の設定領域だけに保存します。GitHub、ログ、Issue、ChatGPTに内容を載せないでください。HAのバックアップにも含まれるので、バックアップの管理にも注意してください。
3. 構成画面で `interval_hours`（1～24、初期値6）と `max_activities`（1～100、初期値10）を設定し、アプリを起動します。構成を変更したらアプリを再起動してください。従来の `auth_state.json` があればそのまま使い、失効時のみ再ログインします。ファイルがなくても認証情報があれば初回ログインを試みます。
4. ログに `OK YYYYMMDD_HHMM` または既存分の `SKIP YYYYMMDD_HHMM` が出ることを確認します。保存先は `\\homeassistant\share\runmetrix\` です。

最初のページに表示された件数を上限として処理するため、`max_activities` を増やしてもRDMの次ページは取得しません。未保存の活動が最初のページから消える前に同期してください。

## 認証・通信の失敗

RDMのログイン状態が失効した場合、設定ファイルのメールアドレスとパスワードを使ってOneASICSの画面から再ログインし、活動一覧を確認した後に `auth_state.json` を保存します。追加認証や画面変更などで失敗したときは、設定した時間間隔で再試行します。短い間隔で繰り返しログインしません。Windowsで手動ログインして [ログイン状態を作成](../tools/windows-auth/README.md)する方法も引き続き使用できます。保存済みデータは削除されません。ログやIssueに認証ファイルの中身を載せないでください。

バージョン0.3.2以降、ログインに失敗すると処理段階と停止位置（例: `OneASICSトップ`）をログに記録します。`メールアドレス入力`で止まった場合は、パスワードの正誤をまだ判定できません。ブラウザーでの成功とアプリの成功は別なので、HA上のログの停止位置を確認してください。URLの認証パラメータはログに記録しません。

バージョン0.3.3以降は読込状態と通信失敗のホスト名・エラーコードも記録します。ページ本文、入力したメールアドレス、パスワード、認証URLは記録しません。`OneASICS/login` で停止する場合、HAからログイン画面の読み込みが完了していない可能性があります。

バージョン0.3.4以降は文書応答と失敗した通信の種類（`document`、`xhr`、`fetch`、`script`）も区別します。HTTP 403 がページ本体か内部通信かを確認するための診断です。認証先から拒否される場合にアクセス制限を回避するものではありません。

## 0.3.5以降の保存形式

CSVはZIP内の元の名前を保持します。通常の活動フォルダーは元ZIPと `lap_form_data-YYYYMMDDHHMM.csv`、`lap_form_score-YYYYMMDDHHMM.csv` の3ファイルです。心拍CSVはこの版では展開対象に含めません。旧活動を通常モードで再命名する処理はありません。

## 0.3.6のクリーン処理

```yaml
interval_hours: 6
max_activities: 10
clean_run: false
```

`clean_run: true` にして保存・再起動すると、取得済み履歴や保存済みファイルの有無にかかわらず、対象活動をサイトから再ダウンロードします。ZIP・CSVを検証してから同じ活動フォルダー全体を置き換えます。ダウンロード・検証の失敗時には旧フォルダーを維持します。

対象は最初のページの最大 `max_activities` 件です。全期間の取得機能ではありません。**ONの間は定期実行でも繰り返すため、検証後はOFFに戻して保存・再起動してください。**

取得履歴は `/share/runmetrix/manifest.json` に記録します。画面ログを読み返しているわけではありません。通常モードでは履歴にある活動はCSVの存在に関係なくSKIPします。Drive Syncが照合済みの古いCSVを削除しても、同じ活動を再ダウンロードし続けないための仕様です。履歴の全削除は不要です。

同じ版以降のDrive Syncと共通の `/share/runmetrix/.sync.lock` で排他します。ロック待ち中は相手側の処理完了後に進みます。
